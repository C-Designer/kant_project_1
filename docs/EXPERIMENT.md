# 실험 규약

## 목적과 범위
향후 코딩 에이전트에 사용할 로컬 LLM의 기초 코드 수정 능력을 비교한다. 이번에는 에이전트·도구 호출·재수정 루프·웹 UI를 구현하지 않는다. 언어는 Python 3.12이며 작은 백엔드 버그 10개를 동일한 조건에서 한 번에 수정하도록 요청한다.

## 개인별 실행과 제출
기본 협업 경로는 `run-model --participant 본인ID --model 전체태그`다. 팀원 각자가 한 모델을 20회 실행하고 `results/본인ID/실행ID/`의 자동 REPORT.md, 작성한 NOTES.md, 원본·측정 로그를 본인 폴더 단위로 push한다. 재실행은 새 폴더에 남겨 이전 결과와 섞거나 덮어쓰지 않는다. 상세 절차는 [개인 실행 가이드](INDIVIDUAL_RUN.md)를 따른다.

역할 분담과 장비 분산은 다른 문제다. 공식 기본 비교는 같은 PC에서 최소 2모델을 실행해야 하므로 팀원이 공통 PC를 나눠 사용하는 방식을 권장한다. 다른 장비의 개인 결과는 환경이 다른 탐색 실험으로 명시하며 속도를 모델의 우열로 직접 비교하지 않는다. 코드 커밋이 개인 결과 push 때문에 달라질 수 있으므로 같은 문제·테스트·설정인지 suite/prompt 해시와 옵션을 함께 확인한다.

자동 보고서의 수치는 실제 로그에서만 계산한다. NOTES.md의 해석·라이선스 확인·민감 정보 검토는 사람이 완료해야 한다. 개인별 제출이 끝나도 Cloud 비교와 팀 최종 모델 선정은 남는다.

## 필수 실험
- 동일 Windows 수업용 노트북에서 서로 다른 Ollama 로컬 모델 2개를 하나씩 실행한다.
- 로컬: 10문제 × 독립 실행 2회 × 2모델 = 40회. 각 실행은 초기 코드와 대화를 리셋한다.
- 워밍업: 모델당 1회, 본 집계와 분리한다.
- Cloud API: B01·B04·B06·B08·B10을 각각 **1회**, 총 5회. 이는 결과 확인 전 정한 비교 세트다.
- Cloud와 비교할 때 동일 5문제의 로컬 **두 반복 모두** 사용한다. 로컬 10회 대 Cloud 5회의 분모 차이를 표시하며 좋은 로컬 응답만 고르지 않는다.
- 공개·가상 데이터만 사용한다. API 키·자격증명·실제 고객 데이터는 코드·로그·Notion·스크린샷에 남기지 않는다.

## 판정과 사전 고정
주 지표는 완전 해결 횟수 / 계획 실행 수(로컬 모델당 20회)다. 공개 테스트와 평가용 테스트를 모두 통과해야 해결이다. 호출 실패는 별도 상태로 기록하며 실패를 성공 응답으로 교체하지 않는다. 성공 응답만의 품질 분석은 별도 분모 n을 표시한다.

보조 지표는 두 번 모두 해결한 문제 수 / 10, 문제별 0·1·2회 해결, 공개/평가 테스트 결과, 구문 오류·형식 오류·시간 초과, 회귀 실패 사례다. 테스트 수로 문제 가중치를 다르게 주지 않는다. 테스트 통과만으로 코드 보안이나 실제 배포 적합성을 보증하지 않는다.

모든 요구사항과 허용 입력은 prompt.md에 명시한다. 명시하지 않은 임의 타입·알 수 없는 필드는 평가하지 않는다. test_hidden.py는 **모델 입력에서 제외한다는 뜻**이며 저장소 읽기 권한이 있는 팀원에게 비밀이라는 뜻이 아니다. 모델에는 prompt.md + starter.py + test_public.py만 전달한다. reference.py와 평가 테스트를 프롬프트에 넣지 않는다.

본 실험 전 문제·테스트·정답·출력 추출 규칙·모델 설정·타임아웃·Cloud 5문제를 확정하고 커밋 SHA를 기록한다. 문제 수정이 필요하면 새 버전으로 전체 본 비교를 다시 실행하고 이전 결과와 섞지 않는다. 예비 점검은 별도 로그로 남긴다. 자동 재요청이나 사람이 코드 수정하는 개입은 하지 않는다.

## 성능 지표
- 전체 모델 응답 시간과 테스트 실행 시간을 분리한다.
- 로딩 시간: load_duration / 1e9 초.
- 토큰 생성 속도: eval_count / (eval_duration / 1e9). 누락 또는 0 이하 duration이면 null과 사유를 남긴다.
- VRAM: Ollama ps의 해당 모델 size_vram / 2^20 MiB. 다운로드 크기·RAM과 구분한다.
- 평균 옆에 유효 표본 수 n을 적는다. 측정 불가를 0으로 채우지 않는다. 전체 응답 시간을 TTFT로 부르지 않는다.
- Cloud는 입력·출력 토큰, 응답 시간(네트워크 포함), 모델 ID, 호출 상태, 단가 기준일과 추정 비용을 기록한다. 추정 비용과 실제 청구는 구분한다.

## 재현성 및 해석
전체 태그·digest·원본 모델·양자화·문서상 최대 컨텍스트·실제 컨텍스트·생성 옵션·CPU/GPU 적재·장비/패키지 버전·실행 순서를 기록한다. 서로 다른 모델을 비교한 결과를 양자화만의 효과로 설명하지 않는다.

동점 또는 작은 차이는 그대로 보고한다. 10문제는 전체 개발 능력의 대표 표본이 아니며, 2반복만으로 통계적 우위를 선언하지 않는다. Cloud 성적, 로컬 후보 선정, 실서비스 도입 권고는 구분한다. 두 로컬 모델이 모두 부족하면 상대적 후보와 실무 도입 불가를 함께 명시한다.

## 아직 팀에서 확인할 항목
- 수업 노트북의 실제 GPU·VRAM·RAM과 Python 평가기 실행 가능 여부. 2060 계열은 사용자 기억일 뿐 확인되지 않았다.
- 서로 다른 로컬 모델 2개, Model Card·License 원문, 사용 목적에 맞는 라이선스, 실제 태그·digest.
- Cloud 모델과 API 사용 권한·비용 한도. 이 문서 작성 과정에서는 유료 API를 호출하지 않았다.
- 실행 옵션·시간/메모리 상한 및 최소 품질 요구. 모든 후보에 동일하게 적용한다.
